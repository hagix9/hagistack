## 1. The Hagistack logo

**Designs considered:**
- **(A) the stacked "H"**, chosen. Two pillars and three layers between them.
  It reads at 16 px and draws with rectangles only.
- **(B) chevrons in a hexagon**, rejected. Hexagons are common in other projects'
  marks, and it does not read at 16 px.
- **(C) a monogram in a rounded square**, rejected. The rounded square is close to
  the OpenStack logo's outline.

**The design:**
- **Colours:** blue `#3E6FE0` and amber `#F0A830`. It avoids OpenStack's red,
  the OpenInfra marks and Rocky Linux's green.
- **Wordmark:** "hagistack", in lowercase geometric strokes.
- **Construction:** no font, no bitmap and no external file. The images are
  generated by `packaging/branding/make-branding.py`, and the same input gives the
  same bytes every time.
- **Licence:** Hagistack's own work, under the MIT License, like the rest of the
  packaging. That licence covers copyright; it is not a trademark licence.

**Files**, all checked by `test_branding.py`:

| File | Use |
|---|---|
| `hagistack-logo.svg` | header brand, mark and wordmark (shown 40 px high) |
| `hagistack-logo-splash.svg` | login page (mark above wordmark) |
| `hagistack-material-brand.svg` | the material theme's inline header logo (no XML declaration) |
| `hagistack-safari-pinned-tab.svg` | Safari mask icon (one colour) |
| `hagistack-favicon.ico` | 16, 32 and 48 px, as PNG entries |
| `hagistack-apple-touch-icon.png` | 180 px |

**Checks:**
- **Safety.** The SVGs hold only `svg`, `title`, `g`, `rect`, `path` and
  `circle`, with geometry and colour attributes. They have no script, event
  attribute, link, `href`, `url()`, style, entity, embedded image or external
  reference. The only URL is the SVG namespace.
- **Rendering.** The images were rendered by macOS QuickLook on white, light
  grey, dark grey and navy backgrounds, and checked by eye. Both logos and both
  icons are legible on all four backgrounds.
- **Not verified:** how the logos look inside a running Horizon. That is part of
  the planned acceptance (section 6).

## 2. Building it into Horizon

**Where the OpenStack logo appears in Horizon 25.7.3.** These were found in the
upstream tree and in the RPMs of the old set:
- the default theme's images in `static/dashboard/img`:
  - `logo.svg`, `logo-splash.svg`, `favicon.ico` and `apple-touch-icon.png`;
  - the Safari mask icon `safari-pinned-tab.svg`, which is the OpenStack mark;
- the material theme's `templates/material/openstack-one-color.svg`, which its
  `header/_brand.html` includes inline, and its unused `-alt` variant.

`404.html`, `500.html` and the material theme's splash refer to
`dashboard/img/...` directly, bypassing the theme lookup. A theme override alone
would therefore have left upstream's logo on those pages.

**How it is built in.**
- In `%prep`, `replace_files` in the definition replaces the seven files in the
  source tree with Hagistack's, after checking that each upstream file exists.
- `collectstatic` then copies Hagistack's images into the collected tree, and so
  does the httpd drop-in, which collects again at run time.
- The theme lookup (`themable_asset`, which falls back to `dashboard/img`) and
  the direct references both get Hagistack's images.
- `local_settings` sets `SITE_BRANDING = 'Hagistack Dashboard'` for the page
  title and the logo's alternative text. Upstream's default is
  `'OpenStack Dashboard'`.

**Not changed**, because they are functional or descriptive: CSS class names
such as `openstack-logo`, package names, and text that names the software
(Horizon, the OpenStack services).

## 3. OpenStack logos still in the release (Owner decision)

A scan of every RPM of the old set found the OpenStack logo outside Horizon:
- **47 packages built with OpenStack's documentation theme** (`openstackdocstheme`):
  46 `*-doc` packages and `python3-os-brick`. Each carries the theme's
  `_static/images/openstack-logo-full.svg`, `-vert.svg`, `logo-full.*` and
  `logo-vert.*`, and its `_static/favicon.ico`.
- The theme comes from a build dependency, so this is not covered by T2, which
  concerns Horizon. Removing the logos changes 44 more definitions (47 packages, minus the three doc packages whose sources B2 already changes).
- `THIRD_PARTY_NOTICES.md` states that these logos are still there.

**Options:**
- **D1. Keep them.** They are the upstream documentation's theme, and the notice
  states it.
- **D2. Remove them from the built HTML.** `genspec.py` would add a step after
  `sphinx-build` that replaces the theme's logo images with Hagistack's. Same
  full rebuild, 44 more specs change.
- **D3. Stop shipping the HTML documentation packages.**

`release_check.py branding` refuses only Horizon's eight logo files (seven replaced, one removed) by content. If D2
is chosen, the docs-theme logos are added to that check.

## 4. Change notices inside the RPMs (B2)

**How the notice is generated.** `genspec.py` takes a new definition key,
`changes = [...]`: one line per change to the upstream tree. From that list:
- **`%changelog`:** the entry lists every change and every patch.
- **`HAGISTACK-CHANGES`:** a file written in `%prep`, holding the project and
  version, every change, the patches with their SHA-256, the statement that
  upstream's copyright and licence notices are kept, and a pointer to the spec
  and `THIRD_PARTY_NOTICES.md`.
- **Every binary package of the source package installs `HAGISTACK-CHANGES`:**
  - a package that already has relative `%doc` files gets it the same way;
  - other packages get it at an explicit `/usr/share/doc/<package>/` path, with
    `%dir` unless the package already owns that directory.

  rpm's handling of relative `%doc` therefore cannot drop the file.
- **Licence:** packages carrying the notice say `… AND MIT` and ship
  `HAGISTACK-LICENSE`, as for any Hagistack-written file.
- **Completeness:** a definition with `patches`, `prep_extra` or
  `replace_files` and no `changes` is refused.
- **Escaping:** `%` is escaped for rpm. A change containing the heredoc
  terminator, or more than one line, is refused.
- **Release numbers:** the six edited definitions are bumped (Neutron 2 → 3, the
  other five 1 → 2), with changelog date Fri Nov 13 2026.

**What the six definitions declare:**

| Source | Binaries | Changes declared |
|---|---|---|
| openstack-neutron 28.0.2-3 | 15 | the two backported upstream commits (ids, Launchpad bugs, files, why); `psutil` bound; the `metadata.py` shebang; placeholders in generated samples; rpm's shebang rewriting |
| python-django-horizon 25.7.3-2 | 3 | `tzdata` requirement; the `manage.py` shebang; the seven images replaced and the `.svg.old` leftover removed; `local_settings` from upstream's example, with `SITE_BRANDING`; compiled catalogues and collected static files |
| python3-qrcode 8.2-2 | 1 | `#!/usr/bin/env python` lines removed |
| python-barbicanclient 7.3.0-2 | 2 | `doc/source/conf.py`, the PDF-only Sphinx extension removed |
| python-keystoneauth1 5.13.1-2 | 2 | `doc/source/conf.py`, `ext.list_plugins` removed |
| python-keystonemiddleware 12.0.0-2 | 2 | `doc/source/conf.py`, the PDF-only Sphinx extension removed |

**Every spec generated before and after:**
- the six change;
- the other **63 are byte-identical**.

**The release refuses a set without the notices** (`release_check.py notices`,
run by `make-rpm-release.sh`). For each source RPM whose spec writes
`HAGISTACK-CHANGES`, every binary built from it must:
- install exactly one `HAGISTACK-CHANGES`, byte-identical to what the spec
  writes;
- have a changelog that lists the changes.

`release_check.py branding` refuses any RPM that installs a file with the bytes
of one of Horizon's eight logo files. It also requires Hagistack's images at
the 12 places in `openstack-dashboard` where they belong: both static trees,
and the two material templates.

**§4(b) is still a legal judgement.**
- The notices are now in the binary RPMs, the SRPM specs and the release
  documents.
- The changed upstream files themselves still carry no notice inside them.
  Hagistack does not edit upstream source text to add one.
- Whether that meets Apache-2.0 §4(b) ("modified files carry prominent
  notices") is not decided here.

## 6. New RPM set and acceptance: plan, waiting for the Owner

**Why GCE.** This Mac is arm64, and the release is built on an x86_64 builder.
No approved local environment exists, and the signed GCE approval needs the
Owner's key, which is not yet pinned.

**Proposed run.** Harness `hs6.py`, one node, run id chosen at approval, for
example `h6b2t2`.

| Item | Value |
|---|---|
| Project and zone | fixed in the harness (the stage 6 project, `asia-northeast1-a`) |
| Resources | the run's own VPC, subnet, IAP and internal firewall rules, router and Cloud NAT, and node **n1** (n2-standard-8, pd-standard 100 GB, Rocky Linux 10.2 x86_64). Nothing else is created, and nothing else is touched. |
| Operations | `init,network,n1,ssh,upload,download,teardown,residual` |
| Limits | US$8 and 6 hours, the harness maximum: the node has a 6 h maximum run duration and the guard tears down at 6 h. Estimate about US$3.5: n1 about 5 h at US$0.498/h, plus disk, NAT and about 0.5 GiB egress. |
| Time | **Not well known.** The only reference: in stage 5, the build VM (e2-standard-8, pd-balanced) existed for 3 h 42 min, including everything around the build. n1 is n2-standard-8 with the slower pd-standard. The steps are ordered so that the candidate is downloaded as soon as it exists. If the limit is reached after that, only the acceptance is lost; it can be repeated in a second run that uploads the downloaded set (`--rpm-source bundle`) instead of rebuilding. |

Steps on n1, all through `hs6.py ssh`/`upload`/`download`:

1. Upload `git archive` of the approved commit.
2. Run `sudo ./hagistack rpm-prepare --rpm-source build`. This builds all 69
   definitions in the pinned container, which gives a **new set**. The 63
   unchanged definitions are rebuilt too: builds are not bit-reproducible, so
   the set must come from one build of the current definitions.
3. Run `make-rpm-release.sh` on the new set, on Rocky Linux 10.2 x86_64, with
   the release tag: the stage 6-4 checks plus `notices` and `branding`. A
   second run must be byte-identical.
4. **`download`** the candidate, and the set directory as one tar, verified by
   SHA-256, straight away.
5. Run `all-in-one` with the new set (`--rpm-source build` reuses it), then
   check:
   - Keystone, Nova, Neutron, Glance and Placement;
   - a guest ACTIVE, with SSH and metadata;
   - Horizon sign-in and the admin pages, with HTTP status checks;
   - the served `logo.svg`, `logo-splash.svg` and `favicon.ico` are byte-equal
     to Hagistack's;
   - no request in the page to another host;
   - a re-run is clean.
6. Deliberately broken copies of the set are refused by `make-rpm-release.sh`.
7. Download the evidence, then teardown and residual.

The set ID and SHA-256 values are recorded once the run has produced them. Old
and new sets are told apart by set identity, release numbers, and directory
names.

**What the Owner does:**
1. Once: run `python3 -I acceptance/stage6/hs6_approve.py --setup` (a
   passphrase key, or `--sk` for a security key) and send the public line, which
   is pinned in `OWNER_SIGNING_KEYS` by a commit.
2. For the run: run `python3 -I acceptance/stage6/hs6_approve.py --run-id <rid>
   --ops init,network,n1,ssh,upload,download,teardown,residual`, after that
   commit.

## Independent audit

**Audit** (separate agent, of `5b5aa51`/`03da6df`). It regenerated the 69 specs
(63 identical), ran the tests, and compared the old set's payloads, the Horizon
source and the Neutron and qrcode sources. Verdict **CONDITIONAL GO**; removal
of the OpenStack logo from Horizon was **NO-GO**.

**HIGH:**
- **H1.** `openstack_dashboard/themes/material/templates/material/openstack-one-color-alt.svg.old`,
  an unused leftover holding the OpenStack wordmark, is in the upstream tree and
  in the old `openstack-dashboard`. Neither `replace_files` nor `UPSTREAM_LOGOS`
  covered it, so the claim "all replaced" was wrong.
- **H2.** `test_branding.py` compared the PNG/ICO bytes. EL10's zlib-ng may
  deflate differently, which would stop `build-own.sh` at its start
  (fail-closed). Not verified.
- **H3.** The time basis of the GCE plan was weak, and the download came last,
  so artifacts could be lost at the 6 h limit.

**MEDIUM:**
- **M1.** The material theme's inline SVG had a fixed width of 712 px, which would
  break its navbar.
- **M2.** `local_settings` is `%config(noreplace)` and the installer edits it, so
  an upgrade would keep the old title.

**LOW:**
- **L1.** A duplicate `%dir` for `openstack-neutron-ml2`.
- **L2.** `%doc` files are skipped with `nodocs`.
- **L3.** `notices` did not check `HAGISTACK-LICENSE` or the MIT tag.
- **L4.** The notice wrote the SRPM as `name-epoch:version`.
- **L5.** Keystone, Placement and Nova make the same kinds of build-time changes
  (sample placeholders, shebang rewriting) but are outside B2.
- **L6.** In `download`: a race between check and `replace`, a linked or
  wrong-mode `downloads/`, and the whole file read into memory.
- **L7.** The evidence `spec-after` was stale.

**Fixes** (this update):
- **H1.**
  - The leftover is removed in `%prep`, after a `test -f`, and declared in
    `changes`.
  - Its sha256 `d48a29e4…55aa2` is added to `UPSTREAM_LOGOS`.
  - A content search of the whole Horizon tree found no other OpenStack-logo
    file. The remaining SVGs are network-topology icons and UI widgets.
- **H2.** The bitmaps are compared by their chunks with `IDAT` decoded. The
  SVGs are still compared byte for byte.
- **H3.**
  - The plan downloads the candidate right after `make-rpm-release.sh`, before
    the install.
  - The time basis is stated as it is.
  - A second run with `--rpm-source bundle` is the fallback.
- **M1.** The inline SVG has no width or height, and a test enforces it.
- **M2.** The installer's managed block also sets `SITE_BRANDING`.
- **L1.** Directory ownership is recognised in `dirs` and in `%dir %attr(…)`
  lines, and a test counts the owners.
- **L3.** `notices` requires `HAGISTACK-LICENSE` and an MIT tag in each binary
  that carries the notice; 2 new refusal tests.
- **L4.** The notice says "source RPM <name> (version <evr>)".
- **L6.**
  - The download is kept with `os.link`, which never overwrites.
  - `downloads/` must be a real directory of the user, mode 0700.
  - The hash is streamed.
  - A test covers a linked `downloads/`.
- **L7.** `spec-after` is regenerated.
- **Unchanged:**
  - L2 is material for the §4(b) decision.
  - L5 is outside the B2 scope, and is an Owner decision if the notices should
    cover every source package.
